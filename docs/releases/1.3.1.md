# bro 1.3.1

## 1Password login matches like 1Password

- `onepassword_find_logins` and `onepassword_fill_login` match by registrable
  domain (Public Suffix List, private section included) with equal scheme and
  port, like 1Password's default "Fill anywhere on this website". A login saved
  on `secure.pnc.com` or as a bare `chase.com` is now found from
  `www.pnc.com` / `secure.chase.com`. Lookalikes (`evilpnc.com`,
  `pnc.com.evil.test`), shared suffixes (`a.co.uk`, `x.github.io`) and
  loopback/IP hosts other than an exact match still do not match.
- Candidates report `match: exact-origin|same-site` (exact first) and the Login
  `username`, so a user-named account can be selected.
- An empty search returns a `next` instruction. Agents previously fell back to
  raw `op` output and native-UI automation.

## Inspect explains the page

`login_form_inspect` adds `hiddenFields`, text-free `accountSwitchers`
(remembered-account select or "other user" control, with `css`/`optionValue`)
and a `hint` for the following cases:

- only a password is fillable because a remembered account hides the username;
- no main-frame inputs exist but visible iframes do, so the form is embedded.

Before this release, the PNC remembered-user page took six DOM-probing calls,
and the Chase dashboard's iframe login returned no reason at all.

## Limits

1Password's per-URL "Only fill on this exact host" / "Never fill" settings and
associated-domain groups are not in the CLI fields bro reads, so they are not
honored. See [the login workflow](../onepassword-login.md).

Upgrade the server, Pi package and browser extension together, then reload
both. No new browser permissions.
