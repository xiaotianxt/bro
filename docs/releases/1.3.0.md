# bro 1.3.0

## CLI-backed password login

- `onepassword_find_logins` filters local 1Password Login metadata by exact URL
  origin, with optional vault/account scope and explicit search authorization.
- `login_form_inspect` returns main-frame origin, document/form handles and input
  indices/types without exposing values or requiring CDP.
- `onepassword_fill_login` fetches only the selected item locally through `op`,
  verifies its saved origin and privately fills selected empty inputs. Credentials
  are absent from public tool arguments/results. Submit is a separate action.
- Pi discovers these together by searching `1Password login`. CDP rejection
  guidance now points password logins here before native UI or extension pause.

A password-manager iframe can remain enabled: isolated extension scripting does
not use the blocked debugger attachment. This is not support for passkeys,
iframe/Shadow DOM fields, CAPTCHA or MFA; those still need appropriate user/native
interaction. The local CLI must be configured and its access approved.

## Security and verification

Private handlers are not MCP tools. Form/document identity, exact origin,
empty-field/type checks, short expiry, and one-shot execution authorization limit
mis-targeted and late fills. Stop revokes a fill waiting on provider approval.
Replies are bound to their authenticated browser connection. Debug output redacts
arguments; WebSocket payload TRACE/DEBUG is excluded even under RUST_LOG=trace.

The credential-free real-browser fixture verifies fill while CDP is blocked,
provider/origin/DOM/document/expiry/autocomplete failures, Stop during delayed
provider read, replay refusal, zero automatic submissions, and exactly one
explicit submission verified by its local server. Synthetic credentials were
absent from public requests/results and captured process logs. An independent
source review drove cancellation and autocomplete-token fixes.

**Real-provider limitation:** development-machine `op` authorization was not ready;
the PNC-related metadata query timed out. No real password was read or bank login
attempted. This release does not claim a completed real 1Password login. See
[setup, threat model and test commands](../onepassword-login.md).

Upgrade the server, Pi package and browser extension together, then reload both
Pi and the extension. No additional browser permissions are required beyond 1.2.0.
The test-only provider feature is disabled in release builds and cannot access
real vaults when enabled.
