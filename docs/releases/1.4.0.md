# bro 1.4.0

Upgrade server, extension and Pi adapter together.

## Migration

| New default | Compatibility entrypoint |
| --- | --- |
| `browser.open` → `targetId` | `browser.flow.start` → `sessionId` |
| `browser.observe` | `browser.flow.observe` |
| `browser.act` with `navigate` / `evaluate` | `browser.flow.act` with `goto` / `eval` |
| `browser.close` | `browser.flow.finish` |

The new API creates owned tabs only. A target pins the browser selected at
acquisition, its authenticated connection, and its tab. Reconnect rejects old
targets rather than acting on replacement tabs with reused IDs. Pi injects a separate `ownerSessionId` and
human-readable `label`; no session-name discovery is required. Close releases
only the owned tab. Legacy flow cleanup overrides and CSS/wait/read_text inputs
remain supported by the same engine. Explicit borrowing is deferred; the new
API never automatically adopts or closes an existing user tab.

Observe defaults to compact a11y, accepts `refId`, `filter`, `depth`, `maxChars`,
`compact`, and is available as an act step. Text mode accepts only `maxChars`
and `cursor`. Facade `maxChars` is at most 20000 and a11y output at most 12000;
legacy flow observation keeps 60000. Refs now survive same-node rereads and find, including scoped and
truncated observations. Ref identity remains tab/frame/document/backend node,
not a selector or label. Navigation, replacement, restart and FIFO retention
expiry fail explicitly. The registry is volatile, capped at 10,000 handles,
and never recycles a handle. Refresh observations after upgrading.

Act validates 1–32 steps (including nonempty evaluation code) before effects
and runs serially, fail-fast. Request cancellation stops subsequent effects;
it does not undo already-dispatched work. Supported
steps: navigate, evaluate, wait (one condition: text, textGone, or refId +
state; timeoutMs default 5000, at most 15000), ref click/fill/select/check/scroll, observe. Trusted click
checks are unchanged; evaluate remains the explicit synthetic escape hatch.
Acknowledgements distinguish document readiness, evaluation, observation and
action dispatch. They do not prove an application-level postcondition.

URL navigation waits for its document's DOMContentLoaded with listeners
installed before dispatch; it does not impose network idle or guess readiness
from nonempty evaluation output. New-tab readiness failures close the owned tab.
`browser.open` is the exception: it returns once navigation is dispatched, and
the target's first observe or act waits up to 4 s for DOMContentLoaded and
readable text, then proceeds.
Same-document navigation verifies the existing loader and its readiness;
returned URLs preserve fragments as well as redirects. Navigation out of
browser-internal source pages uses document-aware webNavigation events without
relaxing debugger access.

A shared allocation owner retains responsibility across item timeout/caller
drop, including late creation replies within the bridge response bound. Cleanup
is connection-bound, and failure retains ownership for explicit retry. Dropped
bridge dispatches remove their pending registrations immediately.

## Settled change reports and role + name targets

Each act click/fill/select/check is one extension call that resolves the
target, acts with the same trusted input, waits until the main frame's DOM has
been quiet for 400 ms (at most 3 s), and reports opened/closed dialogs and
menus, new alerts and invalid fields, new text and navigation. A click with no
visible change says so. Settling is polled from the extension because Chrome
throttles timers in background tabs to about one per second. Changes that start
after a longer quiet gap need an explicit `wait`.

Element steps also accept `role` + `name` instead of `refId`, resolved from the
main frame's accessibility tree when the step runs: exact name first, else a
unique substring; zero or several visible matches fail. This survives menus
that re-render with fresh ids between observe and act. `batch.flow` still
rejects element targets other than CSS.

A click that opens a menu, dialog or listbox also lists refs for the new
layer's controls (the first 12, then the layer ref to observe for the rest),
found by diffing the accessibility tree before and after the click. A
navigation the action started (a form post) holds the settle wait until the
document is replaced, else reports `navigating to`. A role + name miss names
same-named elements with other roles (`menuitem` vs `menuitemradio`).

## Single-action tools, press, and smaller observations

`browser.click`, `browser.fill` and `browser.press` are one act step each with
the same report, so a single action is `{"refId":"kqx12"}` instead of a step
array. `targetId` is optional on observe, act and these tools: each MCP session
remembers the target it last opened or used. `browser.close` still requires it.
The act `press` step (and tool) sends a trusted key to the focused element or a
focused target; Escape closes panels without a close button.

Observations render a native date/time input as one node, filled with an ISO
value (a wrong format names the expected one), instead of its internal
month/day/year spinbuttons, and omit text lines that repeat their parent's name.

Measured on the GitHub token task with deepseek-flash (one run each, about
±15 s run to run): 1.3.2 took 170 s and 73 turns; 1.4.0 before these changes
84–98 s and 41–59 turns, with half of the remaining turns spent observing after
inline reveals, closing an Escape-only panel and filling date parts. A
pi-browser run with one flat tool per action took 86.6 s with half the model
output tokens.

Measured motivation: creating a GitHub fine-grained token through 1.3.x took
about 30 calls after sudo verification, mostly `evaluate` probes, fixed sleeps
and read-backs, and synthetic clicks that React ignored ("Expiration date can't
be blank").

## Pi and fast paths

The server's `bro/default` metadata selects open/observe/act/close and
extract/current.extract/batch.extract/batch.flow. Search is the ninth active Pi
tool, for advanced capabilities. Legacy flow tools are discoverable but not
simultaneously active by default. Older servers without this metadata retain
the adapter's old default catalog. Shutdown closes unfinished targets before
finalizing session-owned tabs and reports failures; reload preserves targets.
The finalizer returns a real tool error for existing tabs it cannot remove and
retains those failed tabs for retry; already-closed tabs count as cleaned.

## Deferred and verification boundary

- No borrowing expansion, branching/loops/rollback,
  persistent ref database, silent retries or click fallbacks.
- No site-specific workflows or changes to installed user skills/configuration.
- An intermediate source checkpoint was validated before the public-facade work;
  its reconstruction patch is kept outside the repository by the implementation
  owner. It is not a separately published release.
- Deterministic checks cover identity, frame navigation, scoped observations,
  readiness, pinned dispatch, validation/fail-fast and Pi lifecycle/catalogs.
  Independent Terra evaluation is separate. No universal speedup or statistical
  superiority is claimed by these source changes.
