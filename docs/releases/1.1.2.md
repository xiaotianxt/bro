# bro v1.1.2 — preserve user focus and renew frame sessions safely

Ref click/scroll and computer input now use scoped Chromium focus emulation
instead of activating the target tab and focusing its window. Background
rendering and scroll-event checks remain intact. Emulation is cleared after
success or failure, same-tab input is serialized, and detached queued input is
cancelled rather than replayed. `tabs_activate` remains available for deliberate
foreground work; it is not a routine input prerequisite.

A debugger lifecycle race is also fixed: consecutive flow steps could reuse
child frame sessions while idle detachment was still in flight. New attachments
now wait for detachment to finish, and frame state is invalidated as detachment
starts. Attachment-loss errors no longer automatically replay commands.

Verification: Rust checks and 46 tests; extension typecheck and 45 tests; all
11 isolated real-browser ref contracts, including cross-site/nested input,
background scroll, preserved tab selection and restored visibility. The
previously failing consecutive fill/select flow now passes. The browser suite
used Chrome for Testing 149 on macOS, not every supported Chromium version.

Focus emulation is an experimental CDP API and temporarily changes the page's
perceived visibility/focus. It does not promise OS-native dialog automation.
See [Input focus](../input-focus.md) for details.

Upgrade server and browser extension together through the normal Homebrew
release flow, reload the browser extension, then reload Pi or start a new
session to refresh the server-owned tool descriptions. The release script also
keeps the tagged Pi installation commands in both READMEs current.
