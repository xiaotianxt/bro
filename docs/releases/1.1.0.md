# bro v1.1.0 — frame-aware refs and reliable scroll workflows

## Highlights

- Native Chromium accessibility snapshots include same-site, cross-site and nested frame trees and Shadow DOM labels.
- Opaque refs bind to the tab, snapshot, document loader and backend node. Detached/replaced nodes and refs from another tab/snapshot fail rather than silently retargeting.
- Existing `browser.flow.act` click/fill/select steps accept `refId`; no manual frame lookup is needed for ref actions.
- Ref-only `scroll` steps can be combined with `read_text` to verify intermediate UI states in one call.
- Scrolling prepares the foreground/frame, scrolls once, waits for rendering, and returns measured offsets, movement and boundary data. This fixes the observed hidden-tab case where scrollTop changed but the page's UI stayed stale.
- Click and scroll share input preparation, including iframe border/padding geometry and rendering synchronization. No synthetic-click fallback or automatic replay is used.
- Form events compose across Shadow DOM boundaries. File upload uses the same document-bound refs.
- No new MCP tool names or runtime dependencies are added. Fresh profiles no longer warn about user-script permission when there are no scripts to restore.

## Upgrade notes

Upgrade the server and extension together, then reload the agent's tool catalog.

- `browser.flow.observe` now defaults to accessibility output. Pass `mode: "text"` explicitly for the former main-frame plain-text behavior.
- Obtain a new snapshot after upgrade; old numeric `ref_N` handles are not portable. New snapshots replace earlier refs for their tab; plain `read_text` does not.
- `get_element_info` now returns bounded JSON details, including scroll state and frame-local coordinate labels.
- Ref scroll is an input operation and brings the target tab/window forward. Extraction and screenshots remain background-capable.
- Chromium 125+ is required for flat child debugger sessions. Live validation used Chrome for Testing 152.

## Verification

- `make check`: 45 Rust tests, 37 extension tests and 20 Pi adapter tests passed.
- Eleven isolated real-browser contract groups passed, including fresh hidden-tab scroll and one-call 100/920/920 UI verification.
- Matched Luna/max scroll trials: both products passed all valid runs. Normal skill-driven bro usage averaged 43.7s / 7 calls / 53.8K processed tokens versus agent-browser CLI's 60.5s / 14 / 162.4K. With equivalent batching hints, time was comparable (38.6s versus 36.7s), while bro used fewer calls/tokens. Two sleep-interrupted cells were excluded and replaced transparently.
- These are small workflow pilots, not engine-speed or universal-success claims. Raw browser sessions are not part of the release.

## Known limits

- One earlier nested-click trial required a model-level retry after dispatch. Application outcomes must still be observed; a dispatch acknowledgement is not proof of application success. This remains a separate investigation.
- Rotated/perspective/flipped iframe input is rejected rather than guessed.
- Rendering synchronization is not a promise that arbitrary network-loaded content has finished.
- Frames and output are bounded; uncommon writing-mode scroll origins report an unknown boundary rather than inventing one.
